## Directory Purposes

**Root Directory:**
- **Purpose:** Framework library root containing core routing, dispatch, and handler registration
- **Contains:** agenthooks.go (route registry), unified.go (unified handler definitions), go.mod
- **Key files:** `agenthooks.go` (entry point for framework users), `unified.go` (unified handler registration logic)

**claude/, cursor/, windsurf/, droid/, gemini/:**
- **Purpose:** Platform-specific adapters that translate between agent JSON schemas and unified event types
- **Contains:** 
  - `types.go`: Event structs with JSON tags matching platform schemas (EventBase + specific event types)
  - `responses.go`: Helper functions to build response structs (e.g., Permit, Forbid, ApproveToolUse, DenyToolUse)
  - `doc.go`: Package-level documentation
  - `*_test.go`: Tests for response builders
- **Pattern:** Each platform has identical structure so developers can understand them consistently
- **Key insight:** `responses.go` returns structured types that work with unified.go helper functions (e.g., cursorPermissionResult, which converts ToolVerdict to cursor.PermissionResult)

**internal/codec/:**
- **Purpose:** JSON serialization layer with platform quirk handling
- **Contains:**
  - `codec.go`: DecodeStdin (strips UTF-8 BOM for Cursor on Windows), EncodeStdout (JSON encoder to stdout)
  - `codec_test.go`: Tests for BOM handling and encoding
- **Why internal:** Users should not directly import codec; it's used by Process and ProcessE internally

**internal/scaffold/:**
- **Purpose:** Template generation for `agenthooks init` command
- **Contains:**
  - `scaffold.go`: Run() function that creates directories, writes template files from templates.go content
  - `templates.go`: Embedded template strings (main.go with all handlers, README.md, .gitignore, policy.json)
- **Why internal:** Not a user-facing package; CLI tool uses it
- **File safety:** Scaffold checks for existing files and refuses to overwrite; creates directories as needed

**cmd/agenthooks/:**
- **Purpose:** CLI tool providing init, install, and build commands
- **Contains:**
  - `main.go`: Command routing, subcommand parsing, implementation of init/install/build
- **Key functions:**
  - `init`: Calls scaffold.Run()
  - `install`: Reads hook binary path, modifies ~/.claude/settings.json, ~/.cursor/hooks.json, etc. to point to binary
  - `build`: Runs `go build` for each platform (macOS/Linux/Windows × amd64/arm64), outputs to dist/
- **Invoked as:** `go run github.com/CheckmarxDev/ast-cx-hooks/cmd/agenthooks init|install|build`

**.github/workflows/:**
- **Purpose:** CI/CD automation
- **Contains:** Hooks-Release.yml (GitHub Actions workflow for releases)
- **Trigger:** Tag-based releases

**docs/:**
- **Purpose:** User-facing documentation and enablement materials
- **Contains:**
  - CONFLUENCE-PAGE.md: Narrative for stakeholder communication (copy-paste into Confluence)
  - DEMO.md: Step-by-step multi-agent demo with scripted test inputs
  - VIDEO-STORYBOARD.md: Video recording guide

## Key File Locations

**Entry Points:**

- **Framework entry:** `agenthooks.go` — exports AddRoute, Dispatch, Process, ProcessE, ClearRoutes
- **Unified handlers:** `unified.go` — exports WhenAgentIdle, BeforeToolCall, AfterFileWrite, BeforePrompt
- **CLI tool entry:** `cmd/agenthooks/main.go` — main() parses os.Args[1] for command (init/install/build)
- **Hook binary entry:** User's main.go (generated by `agenthooks init`) — registers handlers and calls agenthooks.Dispatch()

**Configuration:**

- **Go module config:** `go.mod` — module path and Go version (1.21+)
- **Release workflow:** `.github/workflows/Hooks-Release.yml` — triggers on tags
- **User hook config:** `~/.claude/settings.json` — where install command writes Claude hook path
- **User hook config:** `~/.cursor/hooks.json` — where install command writes Cursor hook paths
- **User hook config:** `~/.codeium/windsurf/hooks.json` — where install command writes Windsurf hook paths
- **User hook config:** `~/.factory/settings.json` — where install command writes Droid hook path
- **User hook config:** `~/.gemini/settings.json` — where install command writes Gemini hook paths (currently manual)

**Core Logic:**

- **Route dispatch:** `agenthooks.go:Dispatch()` — selects handler by route name from os.Args[1]
- **JSON I/O:** `internal/codec/codec.go:DecodeStdin()` and `EncodeStdout()` — handle platform quirks
- **Unified handlers:** `unified.go` — four major functions (WhenAgentIdle, BeforeToolCall, AfterFileWrite, BeforePrompt), each calling AddRoute 5 times (once per platform)
- **Platform adapters:** Each platform's `responses.go` — builds JSON response structs from verdicts

**Testing:**

- **Framework tests:** `agenthooks_test.go` — TestAddRouteAndDispatch, TestProcessReadsStdinAndWritesStdout
- **Codec tests:** `internal/codec/codec_test.go` — BOM handling and JSON encoding/decoding
- **Platform tests:** `*/responses_test.go` in each platform (claude/, cursor/, etc.) — response builder validation

## Naming Conventions

**Files:**

- **Adapter packages:** Lowercase platform name (claude, cursor, windsurf, droid, gemini)
- **Type files:** `types.go` in each package (event definitions)
- **Response builders:** `responses.go` in each package
- **Tests:** `*_test.go` following Go convention
- **Package docs:** `doc.go` in each package
- **Internal packages:** Under `internal/` directory (codec, scaffold)
- **CLI tool:** `cmd/agenthooks/main.go`

**Go Functions (Public):**

- **Core:** `AddRoute(name, fn)`, `Dispatch()`, `Process[I, O](handler)`, `ProcessE[I, O](handler)`
- **Unified handlers:** `WhenAgentIdle(fn)`, `BeforeToolCall(fn)`, `AfterFileWrite(fn)`, `BeforePrompt(fn)`
- **Verdict constructors:** `Resume()`, `Interrupt()`, `Allow()`, `Deny()`, `AcceptWrite()`, `AnnotateWrite()`, `AcceptPrompt()`, `EnrichPrompt()`
- **Event helpers:** `(AgentIdleEvent).IsLooping()`, `(ToolCallEvent).IsShell()`, `(ToolCallEvent).IsMCP()`
- **Platform responses:** `claude.ApproveToolUse()`, `cursor.Permit()`, etc.

**Constants:**

- **Agent IDs:** `AgentClaude`, `AgentCursor`, `AgentWindsurf`, `AgentDroid`, `AgentGemini`
- **Tool kinds:** `ToolKindShell`, `ToolKindMCP`, `ToolKindBuiltin`
- **Route names:** Prefix + dash + event (e.g., "claude-pre-tool-use", "cursor-before-shell")

**Types:**

- **Unified events:** PascalCase + "Event" suffix (AgentIdleEvent, ToolCallEvent, FileWriteEvent, PromptEvent)
- **Verdicts:** PascalCase + "Verdict" suffix (IdleVerdict, ToolVerdict, FileWriteVerdict, PromptVerdict)
- **Platform events:** PascalCase + "Event" suffix (PreToolUseEvent, ShellPreEvent, etc.)
- **Platform responses:** PascalCase + "Result" suffix (PreToolUseResult, PermissionResult, etc.)

**Handler Types:**

- **Unified handlers:** Named function type + "Func" suffix (AgentIdleFunc, ToolCallFunc, FileWriteFunc, PromptFunc)
- **Route functions:** RouteFunc (always the type name, one per registered route)

## Where to Add New Code

**New Unified Hook Category:**

When adding a fourth unified hook (e.g., "BeforeModelSelection"):

1. **Define unified event:** Add `YourEvent struct` to `unified.go` with platform-agnostic fields
2. **Define verdict:** Add `YourVerdict struct` to `unified.go` with verdict constructors
3. **Define handler type:** Add `YourFunc func(YourEvent) YourVerdict` to `unified.go`
4. **Register in each platform:** 
   - Add `YourPlatformEvent` struct to `platform/types.go` (e.g., claude/types.go, cursor/types.go)
   - Add response builders in `platform/responses.go` (e.g., `approveSelection()`, `denySelection()`)
   - Add route registration in `unified.go` inside the public registration function
5. **Example location for main unified handler:** `unified.go` lines 600-700 (after BeforePrompt section)

**Adding Support for a New AI Agent:**

1. **Create new package:** `newagent/` directory
2. **Add types.go:** Define EventBase and all event types (copy claude/types.go as template, adjust JSON tags)
3. **Add responses.go:** Implement all response builders (pattern: convert unified verdict to agent-specific response)
4. **Add doc.go:** Package-level documentation
5. **Update unified.go:** 
   - Add `AgentNewagent` constant to AgentID type
   - Register 4 new routes in each unified handler function (WhenAgentIdle, BeforeToolCall, AfterFileWrite, BeforePrompt)
   - Add platform detection helper if needed (claudeToolKind, droidToolKind, etc.)
6. **Update cmd/agenthooks/main.go:** Add installNewagent function to install command
7. **Update docs:** README.md table of supported agents and hook routes

**New CLI Command:**

1. **Location:** `cmd/agenthooks/main.go`
2. **Add case to main switch:** `case "mycommand": myCommandFunc()`
3. **Implement handler function:** `func myCommandFunc() error { ... }`
4. **Update printUsage():** Document the new command

**Adding Tests:**

- **Unit tests for handlers:** Create `main_test.go` or `handlers_test.go` in hook project (generated by scaffold)
- **Platform-specific response tests:** Add to `platform/responses_test.go` (e.g., claude/responses_test.go)
- **Integration tests:** Test full flow in `agenthooks_test.go` by mocking stdin/stdout

**Utilities and Helpers:**

- **Shared validation:** `internal/helpers.go` (if needed, currently no internal helpers)
- **Platform detection:** Keep in `unified.go` as inline helpers (claudeToolKind, droidToolKind, geminiToolKind, cursorPermissionResult, etc.)
- **Template content:** Expand `internal/scaffold/templates.go` when adding files to scaffold output

## Special Directories

**internal/:**
- **Purpose:** Go convention: packages not meant for external import
- **Generated:** No
- **Committed:** Yes
- **Cleanup:** Never delete; part of framework codebase

**.github/workflows/:**
- **Purpose:** CI/CD automation
- **Generated:** No
- **Committed:** Yes
- **Cleanup:** Leave as-is unless deprecating release automation

**dist/ (created by build command):**
- **Purpose:** Output directory for cross-compiled hook binaries
- **Generated:** Yes (by `agenthooks build`)
- **Committed:** No (typically in .gitignore for hook projects)
- **Cleanup:** Safe to delete; will be regenerated on next build

**User project root (created by init command):**
- **Generated files:** main.go, README.md, .gitignore, policy.json
- **Committed:** Yes (all should be checked in)
- **User responsibility:** Edit main.go to customize handlers, commit policy.json with version control
